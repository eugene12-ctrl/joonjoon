# 벤치마크: 토스뱅크 '키워봐요 적금'

출처
- [디자이너의 아이디어가 금융상품이 되기까지](https://toss.tech/article/rpg-savings) (키워봐요 31일 적금)
- [다람쥐 9마리 캐릭터 디자인](https://toss.tech/article/chipmunk) (키워봐요 적금 캐릭터)

## 1. 토스가 한 일

| 항목 | 내용 |
|---|---|
| 상품 | 토스뱅크 '키워봐요 적금'을 '키워봐요 31일 적금'으로 재설계 |
| 출발 질문 | "어떻게 하면 사용자가 토스뱅크에 애착을 갖고, 자주 들어오게 할 수 있을까?" |
| 기존 문제 | 자동이체만 걸어 두면 캐릭터가 저절로 자라 앱을 열 이유가 없었다. 리텐션이 떨어져 "가입한 뒤 점점 잊히는 적금"이 됐다 |
| 해법 | 직접 저금해야만 캐릭터와 이자가 자란다. 매일 다른 스토리(일일 퀘스트), 대화 선택으로 쌓이는 스탯(매력·지혜·힘), 31일 뒤 스탯 조합에 따라 9가지 엔딩(진화형 다람쥐) |
| 보상 | 매일 5,000원 저금 시 연 10% (비용 안에서 여러 안을 비교해 결정) |
| 성과 | 가입자 **절반이 한 달 중 3주 이상** 저금. **5명 중 1명은 31일 하루도 빠짐없이** 저금. 끝까지 키운 사용자가 새 캐릭터로 돌아오는 경우가 많음(수치 없음) |
| 캐릭터 제작 | 노드 기반 AI 이미지 툴 사용. 프롬프트를 "고정 문장 + 캐릭터별 빈칸" 뼈대로 설계. 연습생 101명 → 데뷔조 9명. 쓸 만한 시안 1장을 얻는 데 처음엔 100장, 나중엔 30장, 2~3장으로 줄어듦 |

## 2. 우리에게 주는 의미

### 2-1. 문제 정의를 토스가 먼저 증명했다 (고객문제발견)
- 토스의 문제는 "자동이체만 걸면 앱을 안 연다"였고, 우리 문제는 "주문할 때만 앱을 연다"다. **같은 문제**다. 금융 앱은 기능이 편할수록 오히려 열 이유가 사라진다.
- 발표 문장 후보: *"토스도 같은 벽에 부딪혔습니다. 편하게 만들수록 고객은 잊었습니다."*
- 기획서의 피벗 이야기와도 맞물린다. 나쁜 경험을 없애면(자동이체, 원스톱 주문) 들어올 이유도 같이 사라진다.

### 2-2. 성과 숫자를 목표치 근거로 쓴다 (고객가치)
- "가입자 절반이 3주 이상, 5명 중 1명이 31일 개근"은 금융 앱의 캐릭터 육성이 실제로 매일 방문을 만든다는 공개 근거다.
- 우리 목표 지표도 같은 형태로 제시한다. 예: "시즌(31일) 참여 고객 중 3주 이상 방문 비율".

### 2-3. 토스의 가장 중요한 원칙: 행동과 성장이 같은 방향
- 토스는 "이 게임을 하면서 왜 저금을 해야 하지?"라는 질문으로 억지스러운 세계관(우주선 수리 등)을 버렸다. 돈이 자라는 것과 캐릭터가 자라는 것이 같은 방향이어야 한다.
- **우리에게 적용:** "왜 시장을 알면 해달이 자라지?"에 바로 답할 수 있어야 한다. 해달이 좋아하는 조약돌을 주머니에 모으는 습성이 이 답이다. **알게 된 것 하나 = 조약돌 하나.** 이 연결이 억지스럽지 않다는 걸 발표에서 한 문장으로 보여 준다.

### 2-4. 가져올 장치

| 토스 장치 | 우리 버전 |
|---|---|
| 31일 시즌, 멀티엔딩 | 31일 시즌. 끝나면 달이가 진화한다 |
| 스탯 3종(매력·지혜·힘) | 예: 호기심(시장 브리핑), 지혜(퀴즈), 꾸준함(연속 출석). 조합에 따라 달이의 모습이 바뀐다(탐험가 달이, 학자 달이 등) |
| 매일 다른 스토리 | AI가 **그날의 실제 시장**으로 스토리를 만든다(아래 2-5) |
| 행동에 캐릭터가 바로 반응 | 퀴즈 정답 즉시 달이 반응과 조약돌 애니메이션 |
| 상태창(레벨·스탯·남은 날) | 그대로 차용 |
| 프롬프트 뼈대(고정 문장 + 빈칸) | `docs/character-prompts.md`의 "공통 스타일 + 상황별 추가"가 같은 구조다 |

### 2-5. 토스와 다른 점 = 우리의 차별점

| 구분 | 토스 키워봐요 적금 | 우리(달이) |
|---|---|---|
| 성장시키는 행동 | 저금(상품 가입이 전제) | 알게 되는 것(가입·매매와 무관) |
| 스토리 | 사람이 미리 쓴 31일치 | **AI가 매일 실제 시장으로 생성**. 시장이 매일 바뀌니 콘텐츠가 끝나지 않는다 |
| 범위 | 토스뱅크 앱 하나, 상품 하나 | **증권과 선물 두 앱을 같은 캐릭터로 연결**, 이후 그룹 계열사로 확장 |
| 개인화 | 같은 스토리, 선택지만 다름 | 고객 수준과 관심(보유 시장 등)에 맞춘 미션 |

핵심 문장 후보: *"토스는 31일치 이야기를 사람이 썼습니다. 우리는 매일 바뀌는 시장이 곧 이야기입니다. AI가 오늘의 시장으로 오늘의 이야기를 씁니다."*

### 2-6. 시행착오로 가져올 교훈 (시행착오·인사이트)
- 캐릭터 시안: 토스도 100장 중 1장에서 시작했다. 우리도 실제 사진 → 탈락 → 무료 일러스트 → AI 생성으로 이어진 과정을 기록해 두면 그대로 시행착오 슬라이드가 된다.
- 작은 화면에서는 장식을 덜고, 캐릭터 중심으로 UI 전체를 맞춘다. 캐릭터를 UI에 얹기만 하면 스티커처럼 떠 보인다.

## 3. 대비해야 할 질문 (토스 글 댓글에서 나온 지적)
1. **"이미 있는 것 아닌가?"** 카카오뱅크 26주 적금, 토스 키워봐요 같은 선례가 있다는 지적이다.
   → 답: 그건 은행 적금이고 저금에 보상한다. 증권사는 매매에 보상하면 과당매매 유도가 된다. 그래서 우리는 **앎에 보상하는 증권사 버전**을 설계했다. 그리고 두 앱과 그룹을 잇는 구조는 유진만 할 수 있다.
2. **"캐릭터 효과를 어떻게 따로 측정하나?"** 
   → 답: A/B 설계를 제시한다. 같은 미션을 캐릭터가 있을 때와 없을 때로 나눠 재방문율을 비교한다.
3. **"고객이 존재 자체를 모르면?"** 인지도 문제다.
   → 답: 앱 첫 화면 진입점, 리테일 영업 현장 안내, 유진쇼츠 같은 기존 채널을 활용한다.
