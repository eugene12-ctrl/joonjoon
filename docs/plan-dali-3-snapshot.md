# 달이 3.0 개발 지시: "산 순간을 기억하는 달이"

이 저장소(joonjoon, 브랜치 feature/dali-assistant)에서 작업한다. 시작 전에 CLAUDE.md, README.md, features/dali/README.md, docs/plan-dali-pro.md, docs/demo-script.md, features/dali/dali-customer.js, dali-rules.js, dali-pro.js, dali.js(매매일지 부분)를 먼저 읽어라. 기존 구조(바닐라 JS, 모듈 없음, config → data → icons → screen → main 순서, 규칙이 숫자를 뽑고 화면은 그리기만 함)를 그대로 지킨다. 새 브랜치 `feature/snapshot`에서 작업하고 main에는 손대지 않는다.

## 0. 한 문장

**달이는 고객이 산 순간과 판 순간의 "상황"을 사진처럼 기억하고, 지금이 그 사진과 같은지 다른지를 한 단어로 말한다. 고객은 아무것도 입력하지 않고, 아무것도 고르지 않는다.**

## 1. 지켜야 할 원칙 (어기면 안 됨)

1. 입력 0. 고객이 치거나 고르는 UI를 하나도 만들지 않는다. 버튼은 "펼치기/접기"와 "끄기"만 허용한다. 알림은 달이가 알아서 걸고, 고객은 끌 수만 있다.
2. 한 화면에 한 문장. 첫 화면은 달이 얼굴 + 단어 하나("샀을 때랑 같아요" / "샀을 때랑 달라요"). 숫자·지수·뉴스 목록·가격 게이지는 첫 화면에 두지 않는다. 문장을 누르면 그 아래에 근거 최대 3줄이 펼쳐진다.
3. 이유를 추정하지 않는다. "왜 샀는지"를 말하지 않는다. 산 순간의 상황(아래 사진 항목)만 기록하고 비교한다.
4. 가격은 비교 축이 아니다. -3.8%여도 사진이 그대로면 "같아요". 가격만으로 "달라요"를 띄우지 않는다.
5. 권유 금지. 사라, 팔아라, 오를 것 같다, 기다려라, 좋은 타점이다 같은 표현을 어디에도 쓰지 않는다. "달라요"는 사실 통보이고 팔라는 뜻이 아니다. 리포트는 평가하지 않고 관찰만 적는다. 손해 쪽 사례도 이익 쪽과 같은 비중으로 보여 준다.
6. 데이터는 전부 가상. 종목명은 실제를 쓰되 공시·실적 같은 실제 사건을 지어내지 않는다. 사용자는 홍길동. 「시연용 가상 화면」 표시는 CLAUDE.md 규칙대로 유지한다.
7. 숫자는 전부 규칙(dali-rules.js)에서 나온다. 화면 코드에 숫자를 쓰지 않는다. 시연마다 같은 숫자가 나와야 한다.
8. 기존 네 장면(morning / intraday / close / month)과 발표자 상자, sessionStorage 흐름("dali-story")을 그대로 쓴다.

## 2. 데이터: 산 순간의 사진 (dali-customer.js)

`DALI_CUSTOMER.trades`의 각 매매에 `buySnap`(산 순간), `sellSnap`(판 순간, 판 경우만)을 추가한다. 기존 `ctx` 문자열 배열은 남겨 두되 화면에선 더 이상 쓰지 않는다. 각 사진은 아래 구조다. 값은 전부 가상이며 20건 모두 채운다. 보유 중인 3건(id 12, 14, 16)은 `buySnap`만 있다.

```js
snap: {
  at: "10/21 10:42",            // 시각
  price: 224000,                // 그때 가격 (비교 축 아님, 표시용)
  // --- 비교 축 5개 (이 5개만 "같다/다르다" 판정에 쓴다) ---
  trend: "up" | "flat" | "down",   // 20일선 기울기
  support: true | false,           // 최근 20일 저점(지지선) 위에 있는가
  volume: "high" | "normal" | "low", // 당일 거래량 / 20일 평균: 1.5배 이상 high, 0.5배 이하 low
  sector: "up" | "flat" | "down",  // 그 종목 업종(반도체, 자동차, 플랫폼)의 5일 흐름
  vol: "calm" | "wild",            // 최근 20일 일평균 변동폭 2% 미만 calm, 이상 wild
  // --- 기록만 하는 항목 (판정에 안 쓰고 펼쳤을 때와 리포트에만) ---
  ma20: 218500, ma60: 205000,      // 이평선 값
  lo20: 212000, hi20: 231000,      // 최근 20일 저점·고점 (지지·저항)
  volRatio: 2.1,                   // 거래량 배수
  dayChg: 1.4,                     // 그날 등락 %
  kospi: 0.6,                      // 그날 코스피 %
  usRef: { name: "미국 반도체", chg: 1.8 }, // 전날 관련 미국 지수
  flow5: { foreign: "buy" | "sell" | "flat", inst: "buy" | "sell" | "flat" }, // 5일 외국인·기관 순매수 방향 (가상)
  event: { kind: "실적" | "배당락" | null, dday: 8 },
  newsTone: "pos" | "neu" | "neg", // 그날 종목 뉴스 톤 (가상. 실서비스에선 AI가 분류)
  mine: { nth: 3, share: 58, avgGap: 1.4, orderType: "지정가", slot: "장초" | "장중" | "마감" }
  // nth: 이 종목 몇 번째 매매, share: 매수 후 내 돈 중 비중 %, avgGap: 내 평단 대비 %
}
```

팔 때 사진(`sellSnap`)은 같은 구조에 `later: 7.1`(판 뒤 2주 가격 변화 %)을 더한다. 기존 `later` 값을 옮긴다.

시연 장면별 "지금" 상황은 `DALI_MARKET[sc]`에 종목별 `nowSnap`으로 둔다. 보유 3종목 × 4장면. 설계 의도:

- 삼성전자(id 12·14, 9/22·9/30 매수): buySnap은 trend up, support true, volume normal, sector up, vol calm. morning·intraday·close 전부 **같음**. intraday는 -3.8%지만 지지선(lo20) 위, 추세 up, 업종 up 유지 → "같아요". 이게 시연의 핵심 장면이다.
- 현대차(id 16): morning·intraday 같음. close에서 sector가 down으로 바뀜 → "달라요" 1건. 펼치면 "자동차 업종이 5일째 내려요" 한 줄.
- month 장면은 보유 종목이 아니라 10월 리포트를 보여 준다(4절).

## 3. 규칙: dali-rules.js에 추가

```js
// 사진 두 장을 5개 축으로 비교. 다른 축 목록을 돌려준다
same(snapA, snapB) → { same: boolean, diff: ["sector", ...] }

// 보유 종목 하나의 지금 상태
alive(sym, sc) → { same, diff, since: "9월 22일", buySnap, nowSnap }

// 첫 화면 한 단어. 보유 종목 전부가 같으면 "same", 하나라도 다르면 "changed"와 그 종목
word(sc) → { state: "same" | "changed", syms: ["현대차"] }

// 펼쳤을 때 근거 3줄 (규칙이 문장까지 만든다. AI 없이도 돈다)
why(sym, sc) → ["추세 위, 지지선 212,000원 위예요", "거래량 평소만큼이에요", "반도체 업종 같이 올라요"]
//   달라진 축이 있으면 그 축을 첫 줄에: "자동차 업종이 5일째 내려요 (샀을 땐 올랐어요)"

// 10월 리포트 숫자 (4절)
report(month = "10") → { ... }
```

축 라벨은 한 곳에 둔다: trend 추세, support 지지선, volume 거래량, sector 업종, vol 변동. "같다"는 5개 축이 전부 같을 때만이다. `support`만 예외로, 산 뒤에 가격이 지지선 아래로 내려갔다가 다시 올라오면 다시 "같음"으로 돌아올 수 있다(상태는 지금 기준).

## 4. 리포트: 산 순간과 판 순간을 나란히

매매일지 월간 화면을 "10월 리포트"로 바꾼다. 리포트는 매매 목록 하나다. 요약 문장, 관찰, 해석, 통계를 넣지 않는다.

한 줄씩: `10/20 SK하이닉스 · +41만 원`. 줄을 누르면 살 때 사진과 팔 때 사진이 두 칸으로 나란히 펼쳐진다. 각 칸은 5개 축을 단어로 보여 주고(추세 ↑, 지지선 위, 거래량 보통, 업종 ↑, 변동 차분), 두 칸에서 다른 축만 진하게 표시한다. 그 아래 한 줄: "판 뒤 2주 +7.1%". 그게 전부다. 사진 두 장을 보고 무엇을 읽을지는 고객이 한다.

`report(month)`는 그 달 매매 목록과 각 매매의 두 사진, 다른 축 목록만 돌려준다.

## 5. 화면: dali-pro.js의 hero()를 바꾼다

첫 화면(오늘 탭) 구성은 위에서 아래로 이것뿐이다.

1. 달이 얼굴 (기존 FACE_S)
2. 단어 하나: `샀을 때랑 같아요.` 또는 `현대차, 샀을 때랑 달라요.` (한 종목만 다르면 종목명을 앞에, 둘 이상이면 "2종목이 샀을 때랑 달라요.")
3. 작게 한 줄: `삼성전자 9월 22일, 현대차 10월 8일부터 보고 있어요`
4. 끝. 그 아래는 비워 둔다.

단어를 누르면 보유 종목별로 `why()` 3줄이 펼쳐진다. 다시 누르면 접힌다. 색은 둘뿐이다. 같음 = 앱 머리와 같은 청록, 다름 = 회색. 등락 빨강·파랑은 펼친 안쪽 숫자에만 쓴다.

기존 hero()의 내용(지수 세 개, 업종 막대, 밤사이 뉴스 목록, 가격 게이지, 보유 목록, 관심 목록, 달이 키우기 버튼)은 **첫 화면에서 모두 뺀다.** 코드는 지우지 말고 `pro.legacy = false`로 꺼 둔다. 관심 종목은 산 순간이 없으니 첫 화면에 나오지 않는다.

장면별 첫 화면:
- morning: "샀을 때랑 같아요." (펼치면 삼성전자·현대차 각 3줄)
- intraday: **똑같이** "샀을 때랑 같아요." 화면이 아침과 바뀌지 않아야 한다. 펼치면 삼성전자 첫 줄이 "오늘 -3.8%지만 지지선 212,000원 위예요"로 바뀐다.
- close: "현대차, 샀을 때랑 달라요." 펼치면 "자동차 업종이 5일째 내려요 (샀을 땐 올랐어요)". 삼성전자는 여전히 같음.
- month: 10월 리포트(4절)로 바로 간다.

알림: "달라요"가 생기는 순간 달이 느낌표가 켜진다(기존 알림 구조). 화면엔 "달라지면 알려 드려요 (끄기)" 한 줄만 두고, 끄기는 sessionStorage에 저장한다.

## 6. 매매일지 탭 (dali.js journalHTML)

줄 형식을 `날짜 종목 · 살 때 [축 2개] · 팔 때 [같음|달라짐] · 손익`으로 바꾼다. 줄을 누르면 4절 (2)와 같은 두 칸 사진. 보유 중인 종목은 팔 때 칸 대신 "지금 [같음]"을 보여 준다. 일간·주간 전환은 유지하되 월간은 리포트로 대체한다.

## 7. AI가 하는 일 (dali-ai.js)

규칙이 문장을 다 만들 수 있으므로 시연은 네트워크 없이 돈다. AI는 한 곳에서만 쓰고, "달이가 지금 쓴 글" 틀(기존 DaliAI.write)을 쓴다.
- "달라요"를 펼쳤을 때 첫 줄: 달라진 축을 사람 말로 한 문장. (시연은 미리 만든 문장, 구조는 facts → 문장)
리포트에는 AI 문장을 넣지 않는다. 실서비스에서 AI가 추가로 맡는 것(코드 주석과 발표 자료에만 적는다): 산 순간 뉴스 톤 분류(newsTone). 사진의 5개 축은 규칙이다.

## 8. 시연에서 빼는 것

조약돌·옷장·달이 키우기·주간 돌아보기·한 달 습관 리포트·팔레트 실험실·"달이와 3개월 뒤"는 첫 화면과 발표자 상자에서 빼고 코드는 남긴다. dali-after.js의 3개월 뒤 화면은 불러오지 않는다. 뉴스 탭은 남기되 시연 대본에서 뺀다.

## 9. 완료 기준

- index.html을 열어 발표자 상자 네 버튼을 차례로 누르면 5절의 장면별 첫 화면이 그대로 나온다. morning과 intraday 첫 화면이 픽셀 단위로 같다(펼치기 전).
- 첫 화면에 숫자가 하나도 없다(날짜 제외).
- 고객이 치거나 고르는 UI가 없다. 버튼은 펼치기/접기, 끄기, 매매일지 줄 펼치기뿐이다.
- 모든 문장에 "사", "팔", "오를", "내릴", "기다", "좋은", "타점" 글자가 없다(검사 스크립트를 하나 만들어 `features/dali/*.js`를 훑는다. 예외: "샀을 때", "판 매매", "살 때", "팔 때"는 과거 기록 표현이라 허용).
- 20건 매매 전부 buySnap이 있고, 판 17건 전부 sellSnap이 있다.
- `DaliRules.word()`, `alive()`, `why()`, `report()`가 네 장면 전부에서 예외 없이 돈다.
- docs/demo-script.md를 새 흐름(아침 → 장중(화면 안 바뀜) → 마감(달라요) → 월말 리포트)으로 다시 쓴다. 3분 안쪽.
- PR 본문은 .github/pull_request_template.md 형식. 체크리스트 네 항목 모두 확인.

## 10. 작업 순서

1. dali-customer.js: buySnap·sellSnap 20건, DALI_MARKET nowSnap 3종목×4장면 (반나절)
2. dali-rules.js: same, alive, word, why, report (반나절)
3. dali-pro.js: hero() 교체, legacy 끄기, 펼치기, 알림 끄기 (반나절)
4. dali.js 매매일지 줄과 두 칸 사진, 월간 → 리포트 (반나절)
5. dali-ai.js 두 곳 연결, 금지어 검사 스크립트, 대본 (2시간)

각 단계마다 커밋 하나(`feat: ...` 한국어 요약). 막히는 게 있으면 임의로 설계를 바꾸지 말고 질문으로 남긴다.
